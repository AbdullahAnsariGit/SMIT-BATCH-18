React Performance Hooks & HOC

Detailed notes on React.memo, useMemo & useCallback

HOC React.memo

React.memo is a Higher-Order Component that memoizes a functional component. It prevents the component from re-rendering if its props have not changed (shallow comparison by default).

How it works

  • Wraps a component and caches the last rendered result.
  • On next render, React compares previous props with new props using Object.is (shallow).
  • If props are the same → skips re-render and reuses the previous result.
  • If props changed → re-renders normally.

Basic Syntax

import React from 'react';

const MyComponent = React.memo(function MyComponent({ name, age }) {
  console.log('Rendered!');
  return <div>{name} is {age} years old</div>;
});

// Or with arrow function
const MyComponent = React.memo(({ name, age }) => {
  return <div>{name} is {age} years old</div>;
});

Custom Comparison Function (optional)

You can pass a second argument to control when the component should re-render:

const MyComponent = React.memo(
  ({ user }) => <div>{user.name}</div>,
  (prevProps, nextProps) => {
    // return true if props are equal (skip re-render)
    // return false if props are different (re-render)
    return prevProps.user.id === nextProps.user.id;
  }
);
Use Cases:
  • Pure presentational / dumb components that receive the same props often.
  • List items in large lists (e.g. TodoItem, UserCard).
  • Components that are expensive to render and whose props rarely change.
  • When a parent re-renders frequently but the child doesn’t need to.

Example – Preventing Unnecessary Re-renders

const ExpensiveChild = React.memo(({ count }) => {
  console.log('ExpensiveChild rendered');
  // Imagine heavy calculation or complex UI here
  return <div>Count from parent: {count}</div>;
});

function Parent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <button onClick={() => setCount(c => c + 1)}>Increment</button>
      <ExpensiveChild count={count} />
    </>
  );
}

Without React.memo, typing in the input would re-render ExpensiveChild every time. With memo, it only re-renders when count changes.

⚠ Note: React.memo only does a shallow comparison of props. If you pass objects/arrays/functions that are recreated on every render, memo will not help unless you also memoize those values (see useMemo / useCallback).

Hook useMemo

useMemo is a React Hook that memoizes the result of a calculation. It only recomputes the value when one of its dependencies changes.

Syntax

const memoizedValue = useMemo(() => {
  // expensive calculation
  return computeExpensiveValue(a, b);
}, [a, b]); // dependency array

How it works

  • On first render → runs the function and stores the result.
  • On later renders → if dependencies are the same (shallow compare) → returns the cached value.
  • If any dependency changed → re-runs the function and updates the cache.

Example 1 – Expensive Calculation

function ProductList({ products, filterText }) {
  // This filter runs only when products or filterText change
  const filteredProducts = useMemo(() => {
    console.log('Filtering products...');
    return products.filter(p =>
      p.name.toLowerCase().includes(filterText.toLowerCase())
    );
  }, [products, filterText]);

  return (
    <ul>
      {filteredProducts.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}

Example 2 – Creating Stable Object / Array References

function Parent({ userId }) {
  // Without useMemo, this object is new on every render
  // → child with React.memo would re-render every time
  const options = useMemo(() => ({
    userId,
    theme: 'dark',
    sortBy: 'date'
  }), [userId]);

  return <Child options={options} />;
}

const Child = React.memo(({ options }) => {
  console.log('Child rendered');
  return <div>User: {options.userId}</div>;
});
Use Cases:
  • Expensive calculations (filtering, sorting, mapping large lists, complex math).
  • Creating objects or arrays that are passed as props to memoized children.
  • Derived data that depends on other state/props.
  • Values used in dependency arrays of other hooks (to keep them stable).

⚠ Don’t overuse useMemo. Only use it when the calculation is actually expensive or when you need a stable reference. Premature optimization can make code harder to read.

Hook useCallback

useCallback is a React Hook that memoizes a function. It returns the same function instance between renders as long as its dependencies haven’t changed.

Syntax

const memoizedCallback = useCallback(() => {
  doSomething(a, b);
}, [a, b]);

useCallback(fn, deps) is equivalent to useMemo(() => fn, deps).

Why do we need it?

In JavaScript, functions are recreated on every render. If you pass a function as a prop to a React.memo component (or use it in a dependency array), a new function reference will cause unnecessary re-renders or effect re-runs.

Example – Stable Callback for Memoized Child

function Parent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // Without useCallback → new function every render → Child re-renders
  const handleClick = useCallback(() => {
    console.log('Button clicked, count:', count);
    setCount(c => c + 1);
  }, [count]); // or [] if you don't need count inside

  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <Child onClick={handleClick} />
    </>
  );
}

const Child = React.memo(({ onClick }) => {
  console.log('Child rendered');
  return <button onClick={onClick}>Click me</button>;
});

Example – Dependency of useEffect

function Search({ query }) {
  const fetchResults = useCallback(() => {
    // fetch logic using query
    console.log('Fetching for', query);
  }, [query]);

  useEffect(() => {
    fetchResults();
  }, [fetchResults]); // safe because fetchResults is stable unless query changes

  return <div>Searching...</div>;
}
Use Cases:
  • Passing callbacks to memoized child components (React.memo).
  • Functions used as dependencies in useEffect, useMemo, or other hooks.
  • Event handlers that should keep the same reference across renders.
  • Optimizing components that receive many function props.

Quick Comparison

Feature React.memo useMemo useCallback
Type Higher-Order Component Hook Hook
What it memoizes Entire component Return value of a function Function itself
When to use Prevent re-render of component Cache expensive calculation / object Cache function reference
Dependency Props (shallow) Dependency array Dependency array
Returns Memoized component Memoized value Memoized function

They work best together

// Parent creates stable values + stable functions
const data = useMemo(() => processData(raw), [raw]);
const onSave = useCallback(() => save(data), [data]);

// Child is protected by React.memo
const Child = React.memo(({ data, onSave }) => {
  // only re-renders when data or onSave actually change
  return <button onClick={onSave}>Save</button>;
});

Best Practices & Common Pitfalls

  • Measure first — Use React DevTools Profiler. Don’t add memoization everywhere.
  • Shallow comparison only — Objects, arrays and functions are compared by reference. Always memoize them if they are passed to memoized children.
  • Empty dependency array — useMemo(() => ..., []) and useCallback(() => ..., []) run only once (like on mount).
  • Missing dependencies can cause stale closures (bugs). Always include everything the function/calculation uses.
  • useCallback does not prevent the function from being created — it only returns the previous instance when deps are equal. The creation still happens, but the reference is stable.
  • Prefer useCallback when the function is passed down or used in deps. Prefer useMemo when you care about the result of a calculation.
React.memo + useMemo + useCallback — Core tools for controlling re-renders and performance in React.
